# 第06章：从零感知机、OR与XOR对照

从仓库根目录运行，使用项目 CPU NumPy 环境：

```powershell
& ./.venv/Scripts/python.exe -B examples/06-perceptron/run.py
```

完整原始记录保存为 `build/experiments/06-perceptron/results.json`；推理参数保存为同目录的 `or-model.json`。运行时读回参数并检查四个预测一致。该文件是推理参数存档，不是中途训练状态恢复；这个极小实验每次从零初始化重跑。

四幅SVG直接使用这次运行的真实参数、数据和每轮日志重建：

```powershell
& ./.venv/Scripts/python.exe -B examples/06-perceptron/run.py --write-figures
```

图源位于 `docs/assets/06-perceptron/`。OR图使用真实边界；XOR终态权重为零，图中如实显示“全部预测正类”，没有绘制一条不存在的分割线。XOR不可能性图是代数论证示意，更新曲线是本次真实日志，二者在正文分别说明。

数据全部是自定义的OR/XOR四点真值表，无下载。输入形状 `(4,2)`，标签形状 `(4,)`，标签严格用 `-1/+1`。参数含2个权重和1个偏置，float64，CPU。零初始化、固定循环次序，无随机采样或打乱，因此种子不适用。

约定：分数 `>=0` 时预测 `+1`；训练在 `y * score <=0` 时更新，包含落在边界上但因预测约定被判为正类的样本。每轮无更新才报告收敛；准确率100%与所有样本严格正间隔需要分别检查。

学习率1，最多30轮。OR应在第6轮完整扫描后停止，共9次更新，参数为 `[2,2]` 与偏置 `-1`；XOR循环30轮，共120次更新，每轮返回零参数，最终准确率50%。数值与形状、手算更新、收敛上界和参数恢复共16项检查；不满足时以非零状态退出。

完整四点表同时用于训练与观察，不提供独立统计泛化评估。XOR不能被单一仿射阈值分类器表示的依据是正文中的矛盾证明；单凭达到训练预算不能证明任意其他数据也不可分。

输出记录实际耗时与输入/标签数组载荷。载荷128字节不包含解释器、NumPy和中间状态，不是进程总内存；未测进程峰值。依赖安装与锁定遵守根目录 requirements 说明。
