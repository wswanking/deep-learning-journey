# 教程写作、图文与排版规范

## 1. 核心概念如何讲清楚

每个核心概念必须回答：

1. **动机**：前面的方法遇到了什么具体问题？
2. **定义**：概念是什么，输入、输出及成立条件是什么？
3. **直觉**：用图和小例子解释它如何工作。
4. **数学**：解释符号，按步骤推导关键关系。
5. **手算**：用足够小的数字走一遍，展示中间结果。
6. **实现**：把公式、张量形状与代码对应起来。
7. **边界**：常见误解、失败条件和适用范围。
8. **检查理解**：给出概念题、计算题或实验题及解答/解析。

不能仅靠“显然”“容易得到”等措辞省略关键推理。新术语首次出现时解释，并链接到前置章节。补充内容要标记为拓展，不打断主线。

## 2. 来源与引用

优先级：经典教材与大学公开课程 → 原始论文 → 框架或模型的官方文档。博客可作补充，不作为关键原理的唯一来源。

已核对的参考入口：

| 代号 | 来源 | 用途 |
| --- | --- | --- |
| DL | [Deep Learning，Goodfellow / Bengio / Courville，2016](https://www.deeplearningbook.org/) | 数学、机器学习、神经网络和生成模型主线 |
| MIT-LA | [MIT 18.06 Linear Algebra，2010](https://ocw.mit.edu/courses/18-06-linear-algebra-spring-2010/) | 线性代数的几何解释与习题 |
| MIT-CALC | [MIT 18.02SC Multivariable Calculus，2010](https://ocw.mit.edu/courses/18-02sc-multivariable-calculus-fall-2010/) | 偏导、梯度和链式法则 |
| D2L | [Dive into Deep Learning](https://d2l.ai/) | 数学与代码衔接、经典网络及注意力实践 |
| CS231N | [Stanford CS231n 官方课程](https://cs231n.stanford.edu/) | 视觉网络、训练方法及视觉主题 |
| CS224N | [Stanford CS224N 官方课程](https://web.stanford.edu/class/cs224n/) | NLP、词表示、Transformer 与 LLM |

章节计划中的来源代号表示拟采用的参考主线，不表示该章已经完成逐节引用。正式写作时补齐教材具体章节/小节、课程年份与讲次，或论文标题、作者、年份、链接。课程主页会变化，应记录实际使用的课程版本。

现代主题的原始论文和实现版本，在对应章节实施时核验后加入；不能编造页码、实验数据或来源。正文关键定义、图示和结论附近使用 `[1]` 等引用，章末给完整条目。重绘图标记“依据……重绘”并说明原图编号（能够核实时）；直接使用图片时说明来源和使用依据。

## 3. 数学记号

沿用标准线性代数与概率记号，必要时与教材说明对应关系。

| 对象 | 约定 | 说明 |
| --- | --- | --- |
| 标量 | $`x, y, \alpha, \eta`$ | 用上下文明确含义，学习率通常用 $`\eta`$ |
| 向量 | $`\mathbf{x}\in\mathbb{R}^{d}`$ | 默认列向量 |
| 矩阵 | $`\mathbf{W}\in\mathbb{R}^{m\times d}`$ | 先定义形状，再参与乘法 |
| 高阶张量 | $`\mathcal{X}`$ | 结合形状表说明轴含义 |
| 参数集合 | $`\boldsymbol{\theta}`$ | 区分单层参数与全部模型参数 |
| 损失 | $`\mathcal{L}(\boldsymbol{\theta})`$ | 说明单样本、批次及归约方式 |
| 概率与期望 | $`p(x),\ p(y\mid x),\ \mathbb{E}[X]`$ | 区分概率质量、密度和随机变量 |
| 导数与梯度 | $`\frac{\partial\mathcal{L}}{\partial w},\ \nabla_{\boldsymbol{\theta}}\mathcal{L}`$ | 梯度对应的变量必须明确 |

例如单样本线性层：

```math
\mathbf{z}=\mathbf{W}\mathbf{x}+\mathbf{b},
\qquad
\mathbf{x}\in\mathbb{R}^{d},
\quad
\mathbf{W}\in\mathbb{R}^{m\times d},
\quad
\mathbf{b},\mathbf{z}\in\mathbb{R}^{m}.
```

若代码使用行批次输入 $`\mathbf{X}\in\mathbb{R}^{B\times d}`$，应明确转换为 $`\mathbf{Z}=\mathbf{X}\mathbf{W}^{\top}+\mathbf{1}_{B}\mathbf{b}^{\top}`$，输出形状为 $`B\times m`$。解释代码中偏置广播与此式的对应关系。

- 行内公式统一使用 ``$`...`$``，保护下标、星号和矩阵换行符不被 Markdown 改写；独立公式统一使用语言标记为 `math` 的三反引号围栏，内部只写 LaTeX，不再包裹 `$$`。这与 [GitHub 官方数学语法](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions) 一致。
- 多行推导必须放在 `math` 围栏内，避免单独的等号、下划线或星号被 Markdown 当成标题或强调。围栏外前后留空行；语法占位符应放在行内代码中。
- 本地构建仍兼容历史美元分隔符，但新教材源文件由 `npm run check:markdown` 拒绝这类独立块；数学围栏与行内公式使用同一严格渲染器，错误公式必须终止构建。
- GitHub 当前不接受 `\operatorname`。自定义直立算子使用标准 TeX 写法 `\mathop{\mathrm{Var}}\nolimits(X)`；展示式中的极值下标可用 `\mathop{\mathrm{arg\,min}}\limits_j`。算子含义与变量须照常定义。
- 数学内容中的小于号使用 `\lt`，避免裸 `<` 被 GitHub 处理为 HTML 后截断公式；命令与后续字母之间留空格。不要把不可见的截断当作公式已通过。
- 每章提供符号表；每个新符号在首次使用附近解释。
- 清楚区分样本编号、层编号、时间步、维度和训练步；上标的含义不得混淆。
- 写出中间推导，解释所用法则或假设；近似等号、期望及条件概率的含义要明确。
- 概率分布、归一化维度、对数底数和数值稳定处理要说明。
- 不把公式做成图片。以构建工具实际支持的 LaTeX 子集为准，确保 GitHub、HTML、PDF 可读。

## 4. 图示标准

每个核心原理至少配一幅直接帮助理解的图；数量由概念需要决定，不设置装饰性配图指标。

**强制要求：教程所有配图使用真正的矢量图，保证放大和打印时的清晰度。**

- Markdown 和 HTML 使用 SVG 作为标准配图格式；PDF 构建保留矢量路径和文字，必要时使用同源导出的矢量 PDF。
- 结构图、流程图、示意图、数学曲线、注意力热图和实验结果图均按矢量方式生成，保留可编辑源文件或生成脚本。
- 不使用 PNG/JPEG/WebP 等位图或截图充当教程配图；更改扩展名、将位图嵌入 SVG/PDF、对低清图片简单放大均不满足要求。
- 引用教材或课程的图时，采用可用的矢量原图，或理解内容后重绘为矢量图，并保留来源说明。
- 图中的线条、箭头、坐标、公式和文字应可清晰缩放；检查中文字体、字号与对比度，避免文字溢出或缺字。

- 图应有编号、标题、说明、正文引用及可读的替代文本。
- 结构图标输入输出、张量形状和数据方向；计算图标清变量和依赖。
- 数学曲线标坐标、单位/量纲、图例和参数；训练曲线说明数据、配置和指标。
- 图中文字、变量名与正文和代码一致，不能只用颜色表达区别。
- 图及可编辑源文件放在对应章节的资源目录；数学曲线由可复现的数据和绘图程序生成。
- Markdown 使用相对路径；主要教学图片应为仓库内可用资源，避免导出依赖外站图片。
- Mermaid 等代码图若用于正式章节，必须生成 SVG，并在 PDF 构建中保留矢量图形；不能留下原始代码块或转换为位图截图。

## 5. 章节排版与阅读节奏

- 一个章节一个一级标题，正文以二级和三级标题展开，避免跳级。
- 开头写学习目标、前置知识和章节导航；结尾写小结、习题及参考文献。
- 段落聚焦一个问题，图示与解释放在相邻位置。
- 表格适用于符号、形状和比较，不用宽表格承载长篇推导。
- 代码块注明语言，优先展示与概念相关的短片段，完整实验链接到对应文件。
- 章节编号使用两位数字；文档、图片和实验保持相同编号。
- 新建章节才加入可阅读目录；尚未实现的章节只在计划中列出，避免虚假的成品链接。

## 6. 本机实验与结果记录

先完成环境调研，再确定实际实验参数。每个实验记录：

| 内容 | 必须说明 |
| --- | --- |
| 环境 | 操作系统、Python、依赖版本、设备与实际运行日期 |
| 数据 | 来源、获取方式、许可、预处理和训练/验证/测试划分 |
| 模型 | 结构、参数量、张量形状和教学目标 |
| 训练 | 随机种子、优化器、学习率、批次、步数/轮数和精度 |
| 执行 | 从仓库根目录运行的命令、配置文件、输出位置 |
| 资源 | 实测耗时和资源占用；未实测的估算必须注明 |
| 结果 | 训练/验证曲线、适合任务的指标、样例及误差分析 |
| 复现 | 检查点保存/恢复、随机性限制及预期输出范围 |

优先为基础实验提供 CPU 路径；后续 GPU 实验按实测显存安排缩小配置、冻结模块或替代实验。小规模从零训练只用于理解机制，不能把它的效果描述为生产级大模型能力。示例结果与本机实测结果必须区分。

## 7. HTML / PDF 构建要求

这部分定义持续验收标准。INF-02 工具链已落地，实际用法和边界见[构建说明](build-guide.md)。

- 同一份 Markdown 和资源生成两个版本，不分别维护 HTML/PDF 正文。
- 首次运行 `npm ci --ignore-scripts` 准备依赖后，从仓库根目录使用 `scripts/build.ps1 -Format html` 或 `scripts/build.ps1 -Format pdf` 构建已完成正式章节；独立样张用 `-Sample`，单章草稿使用 `-Chapter`；正式全书只汇编完成清单。
- 支持单章草稿和按完成清单顺序生成全书；真实源文件登记到 book.json，章节验收后再勾选，不把样张和待办混入正式全书。
- 输出包含目录、章节导航/书签、代码高亮、数学公式和图示。
- SVG 配图在 HTML 中保持矢量显示，PDF 使用矢量嵌入或矢量转换；禁止在构建中将配图栅格化。排版样张必须包含中文标签、箭头、曲线、热图及公式的矢量图，检查输出对象并放大观察清晰度。
- 配置可用中文字体；验证公式、表格、宽图、长代码在 PDF 中的换行和分页。
- 构建前检查缺失图片和本地链接；没有内容的计划章节不得被当作完整章节发布。
- 输出放在 `build/html/` 和 `build/pdf/`，依赖与安装方法可复现。
- 本地导出不等于对外发布；没有用户发布要求时，交付本地结果即可。

## 8. 章节完成标准

章节计划中的完成勾选必须同时满足：

- [ ] 目标、前置知识、导航明确，无未解释的核心术语。
- [ ] 核心概念有动机、定义、直觉、图、数学或必要的形式化解释及小例子。
- [ ] 符号、维度、图文和代码一致，关键推导有中间步骤。
- [ ] 所有配图均为真正的矢量图，源文件/生成脚本可追溯；SVG 中无伪装的位图，HTML/PDF 导出保留矢量，中文标签和放大效果检查通过。
- [ ] 参考来源明确，可追溯到具体章节、讲次或论文。
- [ ] 实验能在记录的环境运行，结果注明实测状态；不适用实验的内容有对应练习。
- [ ] 有常见误区、习题与解析，读者能检查理解。
- [ ] Markdown 源格式检查通过；修改公式后实际复核 GitHub 页面，确认没有公式被当成标题、正文或代码，不能以本地导出代替 GitHub 验证。
- [ ] HTML 与 PDF 实际构建完成，目视检查中文、公式、图表、代码和分页。
- [ ] 完成当前章节专属验收点，更新任务状态及交付记录。

若实验或导出尚未验证，只能标为“进行中”或“待验证”，不能标“已完成”。
